01

The rules are code, not a prompt

The owner writes the mandate and the agent writes each payment, both in .x3. Guard stores each file's SHA-256, so anyone can check that these are the exact files behind the mainnet payment.

A matching hash proves which source was registered. It does not mean X3VM ran on chain: Guard enforces the mandate's compiled terms in its own Rust code and does not compile or run .x3.

    Take the agent's restricted key and call Guard directly with a hand-written policy, bypassing the compiler and every local check.

03

Where protection ends

These are not stopped. They are the limits the proof card lists, plus one budget effect read from Guard's source.

A false outcome report

Not stopped. Guard stores the hashes and amount the agent reports and compares the amount with the quote's floor. It authenticates neither. Each accepted quote takes one outcome.

Source: record_outcome_for · proof card limit 4

The funding wallet's key

Not stopped. Guard does not hold or move the funds, so whoever holds the Solana funding wallet's key can pay anyone without Guard. In invoice_06 the owner signed the deposit by hand.

Proof card limits 1 and 2

The owner's keys

Not stopped. The owner is trusted. The FullAccess key on x3lang.near can rewrite the mandate, approve and redeploy Guard, and the FullAccess recovery key on x3-agent.x3lang.near controls the agent account.

Proof card limit 3 · the keys

Also true

  • The deposit and the payout are linked by 1Click status, timing and amount, not by a cryptographic proof. The two legs are not atomic (limit 5).
  • Guard checks stored .x3 hashes; it does not compile or run .x3. X3VM is not on the deployed authorization path (limit 6).
  • One settlement of about $25. It does not establish production reliability (limit 7).
  • An accepted quote counts against the 24-hour cap even if it is never funded or is later refunded. The budget comes back only as the window rolls (mandate.rs). This errs toward refusing payments, not toward allowing them.

06

Check it yourself

No wallet, key or API key. Steps 2 to 5 run offline; step 6 reads public mainnet RPC and sends nothing.

  1. Clone the pinned commit
    git clone https://github.com/Cyptopimpinainteazy/x3lang && cd x3lang && git checkout aa8e3aeedf79fa0f8d00a95afc7e21afc1ccfc70
  2. Check both .x3 hashes: expect every file OK
    (cd evidence/near-guard-mainnet-invoice06-2026-11-12/source-recovery && sha256sum --check SHA256SUMS)
  3. Compiler refusals: expect 9/9 edits refused at compile time
    python3 scripts/hackathon/x3_wont_compile.py
  4. Compromised model: expect 8/8 refused and the control allowed
    python3 scripts/hackathon/compromised_agent_redteam.py
  5. Grok drain replay: expect 3/3 refused and the control allowed
    python3 scripts/hackathon/replay_grok_wallet_drain.py
  6. Read the mainnet record: expect 19/19 checks not failed; 0 failed, of which one (who controls the funding wallet) is not readable on chain
    python3 scripts/hackathon/observe_mainnet_invoice06.py --out /tmp/observation.json

Python 3.11 or later. If a script reports a missing package, run the README's setup first: python3 -m venv .venv && . .venv/bin/activate && pip install -r x3-lang/requirements.txt pytest.
